Feladat rövid ismertetése
Bevezetés
A Carcomps.hu egy modern architektúrát alkalmazó autóalkatrész-webáruház demóoldal, amelyet a Baranya Vármegyei SzC Radnóti Miklós Közgazdasági Technikum szoftverfejlesztő és tesztelő képzésének vizsgaremekeként fejlesztettük. A projekt célja egy teljes értékű, éles környezetben is működőképes e-kereskedelmi platform megvalósítása volt, amely demonstrálja a modern webalkalmazás-fejlesztés legjobb gyakorlatait.
Az alkalmazás elérhető a www.carcomps.hu címen, és Cloudflare Tunnel technológia segítségével, egy RackHost.hu-n bérelt VPS szerveren fut (Ubuntu 22.04 LTS operációs rendszer).
Cél
A projekt alapvető célja egy olyan platform létrehozása, amelyen a felhasználók autóalkatrészeket böngészhetnek, kereshetnek és rendelhetnek. A rendszer három felhasználói szerepkört különböztet meg: vendég látogató, bejelentkezett felhasználó és adminisztrátor. A platform tartalmaz autó-kompatibilitási keresőt (MMT-szelektor), kosárkezelést, teljes fizetési folyamatot, profilkezelést, garázsfunkciót és adminisztrátori felügyeleti panelt.
Összefoglalás
Az elkészült alkalmazás kielégíti a modern webáruházakkal szemben támasztott elvárásokat: reszponzív megjelenés, biztonságos hitelesítés (JWT, OTP, kétfaktoros azonosítás), valós idejű kosárszinkronizáció a backendlel, valamint adminisztrátori szintű analitika és e-commerce dashboard PDF-exportálási lehetőséggel.

Használt technológiák
Programozási nyelvek és keretrendszerek
Backend: Java 17 (LTS) a JAX-RS (Jakarta RESTful Web Services) szabvány alapján. A JAX-RS lehetővé teszi az annotáció-alapú, keretrendszerfüggetlen REST API fejlesztést, amely könnyen integrálható más Java EE technológiákkal.
Frontend: Angular (TypeScript). Az Angular egységes, komponensalapú fejlesztési modellt nyújt, amelynek segítségével jól szeparálható, újrafelhasználható UI-egységek hozhatók létre. A projekten belül Angular standalone komponenseket és Signals-alapú reaktív állapotkezelést alkalmaztunk.
Adatbázis
MySQL 8.0, a MySQL Java Connector 8.0.23 verzión keresztül csatlakoztatva a backendhez. A relációs adatbázis 29 táblát tartalmaz.
Alkalmazásszerver
WildFly 26.1.1 Java EE alkalmazásszerver. A backend WAR-fájlként kerül telepítésre a WildFly példányra, amely a HTTP kérések kiszolgálásáért és az alkalmazás életciklusának kezeléséért felel.
Fejlesztői eszközök
Az alábbi eszközöket alkalmaztuk a fejlesztési folyamat során:
•	IntelliJ IDEA / NetBeans: Java backend fejlesztői környezet
•	Visual Studio Code: Angular frontend fejlesztői környezet
•	Postman: REST API teszteléshez és dokumentáláshoz
•	Git + GitHub: Verziókezelés és csapatmunka
•	Jira: Projektmenedzsment, sprint-tervezés és munkaidő-nyilvántartás
•	Figma: UI/UX tervezés és prototípuskészítés
Hosting és infrastruktúra
•	RackHost.hu VPS (Ubuntu 22.04 LTS): az adatbázis, a WildFly szerver és a Cloudflare Tunnel daemon futtatása
•	Cloudflare Tunnel: biztonságos, portnyitás nélküli HTTPS-alagút a backend publikus elérhetőségéhez
•	Vercel / statikus hosting: az Angular frontend kiszolgálása
Egyéb technológiák
•	Node.js (npm): Angular CLI és frontend függőségek kezelése
•	Font Awesome: ikonkészlet a frontenden
•	Chart.js: interaktív diagramok az adminisztrátori dashboardon
•	jsPDF: PDF-exportálás az analitika és e-commerce dashboardhoz

Adatbázis
Az adatbázis rövid ismertetése
Az alkalmazás MySQL 8.0 relációs adatbázisra épül, amely 29 táblát tartalmaz. Az adatbázis tervezésénél az adat-integritás, a normalizáció és a lekérdezési teljesítmény egyaránt szempont volt. A táblák közötti kapcsolatokat elsődleges és idegen kulcsok biztosítják. A soft delete (logikai törlés) minta alkalmazásával az adatok nem törlődnek fizikailag, hanem is_deleted jelzővel inaktívként kerülnek megjelölésre, ami lehetővé teszi az auditálást és az esetleges visszaállítást.
Az adatbázis tábláinak csoportosítása
Felhasználókezelés: A users tábla tárolja az összes felhasználói fiókot (email, felhasználónév, jelszó hash, szerepkör, aktiválási állapot, sikertelen bejelentkezések száma, zárolás időpontja, időzóna). Kapcsolódó táblák: addresses (szállítási és számlázási cím), user_twofa (kétfaktoros hitelesítés titka és helyreállítási kódjai), sessions (JWT munkamenetek tokennel és lejárati idővel), login_logs (belépési napló IP-cím és user-agent adatokkal), user_logs (felhasználói tevékenységnapló), email_verifications (e-mail-megerősítési tokenek), password_resets (jelszó-visszaállítási tokenek).
Termékkatalógus: A parts tábla tartalmazza az alkatrész-rekordokat (SKU, név, kategória, ár, készlet, státusz, aktív jelző, gyártói hivatkozás). A manufacturers tábla a gyártók nevét és országát rögzíti. A part_images tábla az alkatrészekhez rendelt képek URL-jét és elsődleges jelzőjét tárolja. A part_variants tábla a termékváltozatokat (név, érték, felárszorzó) kezeli. A part_compatibility tábla rögzíti, hogy egy alkatrész melyik járműtípushoz és jármű-rekordhoz kompatibilis.
Járműadatbázis: A cars, motors és trucks táblák tartalmazzák a különböző járműkategóriák márkáit, modelljeit és évjárattartományait. A user_vehicles tábla a felhasználók mentett járműveit rögzíti járműtípus, jármű-azonosító és évjárat szerint.
Rendelési folyamat: Az orders tábla a rendelési fejlécet rögzíti (felhasználó, státusz, időbélyeg). Az order_items tábla a rendelési tételeket tárolja alkatrész-hivatkozással, mennyiséggel és egységárral. Az order_logs tábla az állapotváltozásokat naplózza. A cart_items tábla a felhasználók aktív kosártételeit tartja nyilván.
Fizetés és szállítás: A payments tábla a fizetési tranzakciókat rögzíti (rendelés, összeg, módszer, státusz). A refunds tábla a visszatérítéseket kezeli. A shipping_methods tábla az elérhető szállítási módokat és áraikat tárolja. A shipping_status tábla a szállítási állapotot és a csomagkövetési számot rögzíti. Az invoices tábla a számla PDF URL-jét és a kapcsolódó rendelés hivatkozását tartja nyilván.
Vélemények és analitika: A reviews tábla a felhasználói értékeléseket (csillagszám, szöveg, alkatrész- és felhasználó-hivatkozás) tárolja. A page_statistics tábla az oldalmegtekintési és egyedi látogatói adatokat naplózza. A stock_logs tábla a készletváltozásokat rögzíti auditálási célból.
ER-diagram
Az adatbázis entitás-kapcsolati diagramja a projekt dokumentációs repositoriumban található. A diagram tartalmazza a táblák összes attribútumát, az elsődleges kulcsokat (PK) és az idegen kulcsokat (FK), valamint a táblák közötti egy-a-többhöz és több-a-többhöz kapcsolatokat.

Fejlesztési módszertan
A fejlesztés Scrum-alapú agilis keretrendszer szerint folyt, amelynek munkáit Jira projektmenedzsment eszközben rögzítettük. Az egyes taskok részletezték a feladatot, a becsült és tényleges munkaidőt, valamint a hozzárendelt fejlesztőt. A verziókezelést GitHub biztosította, három főágon: backend_dev, frontend_dev és Documentations.
Sprint-bontás
1. sprint – Tervezési fázis (szeptember 1–18.)
A csapat ebben az időszakban elvégezte a projekttervezést: meghatározta az alkalmazás fő funkcióit, a szükséges technológiai stacket, és elkészítette a kezdeti adatbázis-sémát. A Jira-projekt felállítása és a GitHub-repository inicializálása szintén ebben a szakaszban történt.
2. sprint (szeptember 19. – november 14.)
A végleges designterv elkészítése Figmában. A backend API-sablon létrehozása JAX-RS alapon, a WildFly konfiguráció beállítása. A felhasználói regisztrációs és bejelentkezési folyamat megvalósítása JWT-tokennel, beleértve a jelszókészítési validátorokat és az e-mail-formátum ellenőrzést.
3. sprint – Adminisztrátori funkciók
Az adminisztrátori panel megvalósítása: új termék felvétele (képfeltöltéssel), meglévő termékek listázása és részleteinek megtekintése, e-commerce dashboard (rendelési statisztikák, havi forgalom diagram, top termékek), és analitika dashboard (oldalmegtekintések, egyedi látogatók, aktív felhasználók, PDF-export).
4–5. sprint – Felhasználói funkciók és tesztelés
A felhasználói felület teljes körű megvalósítása: főoldal kategóriakártyákkal, terméklista szűrővel és MMT-szelektor komponenssel, termékrészlet-oldal képgaléria és értékelések funkcióval, kosárkezelés backendszinkronizációval, teljes checkout folyamat (kosár → szállítási adatok → fizetési mód → nyugtázás), profil- és garázsoldalak, OTP e-mail-megerősítés, kétfaktoros hitelesítés QR-kódos beállítással és helyreállítási kódokkal. A sprint végén megkezdődött a unit tesztek és a manuális tesztesetek meghatározása.
6. sprint – Tesztelés, hibajavítás
A manuális és unit tesztek lefuttatása, bug reportok készítése a Jirában. Az azonosított hibák javítása. Angol nyelvű bemutató előkészítése a próbavizsgára.
7. sprint – Utolsó simítások
Kódminőség javítása, éles környezeti tesztelés, dokumentáció véglegesítése, deployment ellenőrzése.

A projekt során háromféle tesztelési módszert alkalmaztunk, amelyek kiegészítik egymást a szoftverminőség átfogó biztosítása érdekében.

Oldal működésének részletes leírása
Vendég felhasználó
A www.carcomps.hu főoldalán a látogató egy reklámszalag-slidert, majd alatta az elérhető alkatrész-kategóriákat látja kártyás elrendezésben. Az MMT-szelektor (Márka–Modell–Típus legördülő menük sorozata) lehetővé teszi a járműspecifikus keresést: a márka kiválasztása után dinamikusan szűkül a modellek listája, majd az évjárattartomány is a kiválasztott modell adatai alapján töltődik be.
A navigációs sávban keresőmező, garázs-, kosár- és felhasználó-ikon található. Bejelentkezés nélkül a garázs és a kosár funkció nem érhető el, a rendszer a bejelentkezési oldalra irányít.
Bejelentkezés és regisztráció
A regisztrációs oldalon a felhasználó megadja felhasználónevét, e-mail-címét, vezeték- és keresztnevét, telefonszámát, jelszavát és jelszavának megerősítését. A jelszónak legalább 8 karaktert, nagybetűt, számot és speciális karaktert kell tartalmaznia. Sikeres regisztrációt követően a rendszer a bejelentkezési oldalra irányít.
A bejelentkezési folyamat:
1.	Az e-mail és jelszó megadása után a szerver JWT-tokent ad vissza, amelyet a kliens a localStorage-ban tárol.
2.	A rendszer OTP-kódot küld a regisztrált e-mail-címre, amelyet a felhasználónak meg kell adnia a hatjegyű mezősorban.
3.	Ha a felhasználónál kétfaktoros hitelesítés van beállítva, az OTP-lépést az authenticator-alkalmazásban megjelenő 6 számjegyű kód megadása váltja fel.
4.	Sikeres azonosítás után a rendszer szerepkör alapján irányít tovább: admin felhasználók az adminisztrátori panelre, normál felhasználók a főoldalra kerülnek.
Termékböngészés
A terméklista oldalon az oldalsó szűrőpanelen belül kategória és gyártó szerint szűrhetők a termékek. Az URL-slug alapú navigáció lehetővé teszi, hogy egy adott kategória közvetlen linkkel érhető el. A termékek kártyás megjelenítésben láthatók képpel, SKU-val, kategóriával, árral és raktárkészlettel. A mennyiségszabályzó és a "Kosárba" gomb közvetlenül a kártyán elérhető. Az "elfogyott" állapotú termékeknél a gomb inaktív. A termékkártyán a kép és a terméknév kattintható, a termékrészlet-oldalra irányítva.
A termékrészlet-oldalon a fő kép mellett bélyegképes galéria is megjelenik, ha az adott termékhez több kép áll rendelkezésre. A termék adatai (raktárkészlet, gyártó, státusz) és a vásárlási gombok mellett értékelések is láthatók. A lap alján füles elrendezésben elérhető a termékleírás és a vásárlói vélemények listája.
Fizetési folyamat
A checkout négy lépésből áll, amelyeket egy vizuális progress indicator követ végig:
1.	Kosár: Az összes kosártétel listája képpel, márkalogóval, terméknévvel, mennyiségszabályzóval és törlési gombbal. A jobb oldalon az összegzőpanel mutatja a részösszeget, az ingyenes szállítást és a végösszeget.
2.	Szállítási adatok: A felhasználó megadja a szállítási nevet, várost, irányítószámot, országot, telefonszámot és lakcímet. Az "Automatikus kitöltés" gomb a profilban tárolt vagy korábban mentett szállítási adatokat tölti be.
3.	Fizetési mód: Jelenleg csak a készpénzes fizetés érhető el. A Mastercard, VISA és PayPal opciók szürkítve, inaktívan láthatók, jelezve a jövőbeli fejlesztési irányt.
4.	Nyugtázás: A rendelés véglegesítése után megjelennek a szállítási adatok, a fizetési mód és a megrendelt tételek listája. A rendszer e-mail-értesítést küld a rendelés részleteivel.
Felhasználói profil és garázs
A profil oldalon kártyás elrendezésben szerkeszthetők a személyes adatok: teljes név, felhasználónév, e-mail-cím, jelszó, telefonszám, szállítási cím és a kétfaktoros hitelesítés beállítása. Szerkesztéskor modális ablak nyílik, amelyben az érintett adatmező módosítható. Ha kétfaktoros hitelesítés aktív, e-mail- vagy jelszóváltoztatáskor a rendszer először a TFA-kód megadását kéri. A "Rendeléseim" kártyán a felhasználó megtekintheti korábbi rendeléseit azok státuszával és tételeivel együtt.
A garázs oldalon a felhasználó mentett járműveit kezelheti: új járművet adhat hozzá márka, modell és évjárat kiválasztásával (az adatok a backend járműadatbázisából töltődnek), és a mentett járműveket bármikor törölheti. A főoldalon a garázs-ikonra kattintva a mentett járművek gyorspanelből kiválasztható aktív jármű a termékszűréshez használható.
Adminisztrátori panel
Az adminisztrátori panel csak admin szerepkörű, bejelentkezett felhasználók számára érhető el (adminGuard). Négy fő szekciót tartalmaz:
•	Új termék felvétele: járműkategória, gyártó, SKU (automatikusan nagybetűsre konvertálva), terméknév, kategória, ár, készlet, státusz és opcionális képfeltöltés. A létrehozás után a rendszer SKU alapján megkeresi az újonnan létrehozott termék azonosítóját és feltölti a képet.
•	Jelenlegi termékek: az összes termék rácsnézetes listája szűrési lehetőséggel (keresés, státusz, kategória). Egy termékre kattintva jobbról becsúszó részletpanel jelenik meg a termék összes adatával.
•	E-Commerce Dashboard: regisztrált ügyfelek száma és aktivitási aránya, rendelések száma státusz szerinti bontásban (függőben, szállítás alatt, teljesített), havi rendelési diagram, legtöbbet vásárolt termékek rangsora. A dashboard PDF-formátumban exportálható.
•	Analitika Dashboard: oldalmegtekintések, egyedi látogatók, regisztrált felhasználók száma, aktív felhasználók valós idejű száma sparkline vizualizációval, havi rendelési diagramm. Ez a dashboard szintén exportálható PDF-be.

Fejlesztői dokumentáció
API alap URL
Az összes backend végpont az alábbi alap URL-en érhető el:
https://api.carcomps.hu/vizsgaremek-1.0-SNAPSHOT/webresources/
A jelölésekben {{baseUrl}} erre az alap URL-re utal.
Hitelesítés
A védett végpontok JWT-token alapú hitelesítést igényelnek. A tokent a bejelentkezési válaszból kell kinyerni, és minden kérés HTTP-fejlécébe token kulcsként kell elhelyezni. Az adminisztrátori végpontok ezen felül admin szerepkört igényelnek.
HTTP protokollok
A kommunikáció során az alábbi HTTP-metódusokat alkalmaztuk:
A GET metódus adatok lekérésére szolgál. A paramétereket query string formájában adjuk át, a válaszok gyorsítótárazhatók. A POST metódus új erőforrások létrehozásához és tranzakcionális műveletekhez használatos; az adatokat a kérés törzsében küldjük JSON formátumban. A PUT metódus meglévő erőforrások frissítésére szolgál. A DELETE metódus soft delete műveletek végrehajtásához használatos, a rekordok fizikailag nem törlődnek.

A projektben való rétegek felépítése
A backend JAX-RS projekt négy rétegre tagolódik, a klasszikus N-tier architektúra elvei szerint.
Config réteg
A konfigurációs réteg az alkalmazás indulásához szükséges beállításokat tartalmazza.
•	CorsFilter: A Cross-Origin Resource Sharing (CORS) házirendet kezeli. Engedélyezi az Angular frontend URL-jéről érkező kéréseket, beállítva az Access-Control-Allow-Origin, Access-Control-Allow-Methods és Access-Control-Allow-Headers fejléceket. Ez szükséges, mert az Angular fejlesztői szerver és a WildFly különböző porton fut.
•	Database: Az adatbázis-kapcsolat inicializálásáért felelős osztály. Betölti a JDBC URL-t, a felhasználónevet és a jelszót, és kezel egy ConnectionPool példányt a hatékony kapcsolatkezelés érdekében.
•	Token: A JWT-tokenek generálásáért és ellenőrzéséért felelős segédosztály. Tartalmazza a token aláírásához szükséges titkos kulcsot, az érvényességi idő beállítását és a payload kinyerésének logikáját.
Model réteg
A modell réteg az alkalmazás adatstruktúráit reprezentálja Java osztályok formájában. Minden osztály egy adatbázistáblának felel meg, és az összes adatmező getter-setter metódusával együtt tartalmazza a szükséges validációs annotációkat.
Főbb modellosztályok: User, Address, Part, PartImage, PartVariant, PartCompatibility, Manufacturer, Car, Motor, Truck, UserVehicle, CartItem, Order, OrderItem, Payment, Invoice, Review, Session, UserTwofa, EmailVerification, PasswordReset, PageStatistic, StockLog.
Controller réteg
A controller réteg fogadja a beérkező HTTP kéréseket, elvégzi az alap bemeneti validációt, meghívja a megfelelő service metódust, és visszaadja a HTTP-választ JSON formátumban.
•	ApplicationConfig: Az alkalmazás JAX-RS konfigurációját és az alap URL-prefix beállítását tartalmazza.
•	UserController: Felhasználói műveleteket kezel (regisztráció, bejelentkezés, adatlekérés, frissítés, törlés, aktiválás).
•	PartController: Termékekhez kapcsolódó kéréseket kezel.
•	ManufacturerController: Gyártói adatokat kezel.
•	CarController, MotorController, TruckController: A három járműkategória adatait kezelik.
•	CartItemController: Kosárkezelési kéréseket kezel.
•	OrderController: Rendelési folyamatot kezel.
•	OrderItemController: Rendeléstételeket kezel.
•	PaymentController: Fizetési tranzakciókat kezel.
•	InvoiceController: Számlaadatokat kezel.
•	ReviewController: Értékeléseket kezel.
•	AddressController: Szállítási és számlázási címeket kezel.
•	PartImageController: Termékképeket kezel, beleértve a multipart/form-data feltöltést.
•	PartVariantController és PartCompatibilityController: Termékváltozatokat és -kompatibilitást kezelnek.
•	TFAController és UserTwofaController: Kétfaktoros hitelesítést kezelnek.
•	JWTController és SessionController: Token-érvényesítést és munkamenet-kezelést végeznek.
•	OTPController és EmailController: E-mail küldési és OTP-ellenőrzési funkciókat kezelnek.
•	PasswordResetController: Jelszó-visszaállítási folyamatot kezel.
•	AnalyticsController: Statisztikai adatokat ad vissza admin felhasználóknak.
•	UserVehicleController: Mentett felhasználói járműveket kezel.
Service réteg
A service réteg tartalmazza az üzleti logikát. Közvetlenül kommunikál az adatbázissal a Database osztályon keresztül, elvégzi az összetett validációkat, és adja vissza a feldolgozott adatokat a controllernek.
•	UserService: Felhasználói műveletek validációját és adatbázis-interakcióját tartalmazza; jelszavak hash-elése, token-generálás, szerepkör-ellenőrzés.
•	PartService: Termékadatok kezelésére, szűrési logikára és készletváltozás-naplózásra vonatkozó metódusokat tartalmaz.
•	OrderService: Rendelési tranzakció logikáját tartalmazza: kosárból rendelés létrehozása, rendelési tételek generálása, fizetés feldolgozása.
•	TimetableService (jelen esetben: AnalyticsService): Statisztikai adatok összesítésének logikáját tartalmazza.
•	SubjectService (jelen esetben: ManufacturerService, CarService stb.): Az egyes entitások CRUD-logikáját tartalmazzák.

Főbb komponensek
MainHeaderComponent: A sticky navigációs sáv. Tartalmaz egy keresőmezőt debounce-olt keresési logikával, garázs-dropdownt a mentett járművekkel, kosár-dropdownt az aktuális kosártételek listájával és összegével, valamint felhasználó-dropdownt a profil- és kijelentkezési lehetőségekkel. Bejelentkezési állapottól és kosártartalomtól függően dinamikusan változik a megjelenése.
MMTSelectorComponent: Egymáshoz kaszkádolt legördülő menük (márka → modell → évjárat) a járműspecifikus alkatrész-kereséshez. Az adatok a backend járműadatbázisából töltődnek be, és a kiválasztott márka alapján szűkül a modellek listája, majd az évjárattartomány.
CategoryCardComponent (FilterCardComponent): A főoldalon megjelenő kategóriakártyák. Az összes terméket és képet párhuzamosan kéri le a backenből (forkJoin), majd kategóriánként összesíti a termékszámot és az első elérhető képet rendeli hozzá. Az URL-slug normalizálás NFD-dekompozícióval és ékezet-eltávolítással történik, hogy az URL-ek érvényesek maradjanak.
ProductListComponent: A terméklista a kategória URL-slug alapján szűri a termékeket. A FilterService-szel reaktívan követi az aktív szűrők változásait. Ha nincs aktív szűrő, az összes terméket megjeleníti.
ProductCardComponent: Egyetlen termékkártya komponens. Mennyiségszabályzót és kosárba helyező gombot tartalmaz. A kosárba helyezés után 3 másodperces cooldown aktív, amely alatt a gomb ellenőrző ikont mutat. Ha a termék elfogyott vagy inaktív, a gomb le van tiltva.
FilterComponent: Az oldalsó szűrőpanel háromszintű szűrést kínál: összes kategória, összes gyártó, és kategóriánkénti gyártók szekciók. A szekciók összecsukhatók. Az URL-alapú kategórianavigáció esetén az érintett kategória automatikusan bejelölésre kerül.
CartComponent: A kosár oldal a backendről szinkronizált kosártételeket mutatja. A mennyiség módosítása soft delete és újralétrehozás kombinációjával szinkronizálódik a backendlel. Az egyes tételek neve fölé húzva tooltip jelenik meg a termék részletes adataival.
CheckoutProgressComponent: A négy lépéses fizetési folyamat vizuális haladásjelzője. Az aktuális lépéstől korábbi lépések "teljesített" állapotúak (pipával), a következők inaktívak.
DeliveryComponent: A szállítási adatok bekérő oldal reaktív form-validációval. Az "Automatikus kitöltés" gomb a profilban mentett cím vagy a korábban megadott szállítási adatok alapján tölti ki a mezőket.
AdminLandingComponent: Az adminisztrátori főoldal négy navigációs kártyával. A kártyákra kattintva az adminGuard által védett aloldalak töltődnek be.
AnalyticsComponent és EcommerceDashboardComponent: Mindkét dashboard a GetAllStatsService-en keresztül lekéri a statisztikai adatokat, azokat Chart.js-sel vizualizálja, és lehetővé teszi a jsPDF alapú PDF-exportálást.
OtpComponent: Hatjegyű OTP bevitelére szolgáló modális dialóg. Mező-to-mező automatikus fókuszugrással, vágólapbeillesztés-kezeléssel és 60 másodperces újraküldési visszaszámlálóval.
TfaVerifyDialogComponent: A kétfaktoros hitelesítési kód bevitelére szolgáló modális dialóg, amelyet bejelentkezéskor TFA aktiválása esetén, illetve profilmódosításkor (e-mail- vagy jelszóváltoztatás esetén) jelenít meg a rendszer.
ProfileInfoSelectorComponent: A profiloldalon kártyás elrendezésben szerkeszthető felhasználói adatok. A 2FA szekció tartalmazza a QR-kód megjelenítést, a titkos kulcs feltárás/másolás lehetőséget, az authenticator-kód beviteli lépést és a helyreállítási kódok letöltési/másolási funkcióját.
Szolgáltatások
AuthService: Az alkalmazás hitelesítési állapotát Angular Signals segítségével kezeli. A localStorage-ból inicializálja a bejelentkezett felhasználó adatait (e-mail, felhasználónév, névadatok, telefonszám, szerepkör, azonosító). Az isAdmin() signal alapján különbözteti meg az admin és a normál felhasználókat.
CartService: A kosár állapotát Signal alapú reaktív tárolóban kezeli. A loadCartFromBackend() metódus forkJoin-nal párhuzamosan kéri le a kosártételeket, a termékképeket, a gyártókat és a termékadatokat, majd ezeket összekapcsolja. A mennyiség módosítása és a törlés soft delete + create kombinációval szinkronizálódik.
FilterService: Az aktív kategória- és gyártószűrőket Set adatstruktúrában tárolja Signal-ként. A matchesFilters() metódus határozza meg, hogy egy adott termék megfelel-e az aktív szűrőknek.
BreadcrumbService: Az URL-navigáció alapján dinamikusan generálja a morzsa-navigáció elemeit. A termékoldalakra vonatkozó bejegyzéseknél az utoljára meglátogatott kategóriát tárolja, és a termék nevét a backendből kapott adattal frissíti.

TELEPÍTÉSI ÚTMUTATÓ
Rendszerkövetelmény
Az alkalmazás böngészőalapú webalkalmazás, ezért sem a végfelhasználónak, sem a fejlesztőnek nem szükséges semmilyen szoftvert telepítenie. Az alkalmazás teljes egészében egy távoli szerveren fut, és böngészőn keresztül érhető el.
A használathoz szükséges minimális feltételek:
Bármilyen asztali számítógép, laptop, táblagép vagy okostelefon
Stabil internetkapcsolat
Támogatott böngészők: Google Chrome, Mozilla Firefox, Microsoft Edge, Safari
Az optimális megjelenítéshez és teljesítményhez az adott böngésző legfrissebb verziójának használata ajánlott.
 
A program telepítése
Felhasználói hozzáférés
Az alkalmazás telepítés nélkül, közvetlenül elérhető a következő címen:
https://www.carcomps.hu
Regisztráció után a felhasználó azonnal hozzáférhet az összes felhasználói funkcióhoz. Adminisztrátori hozzáféréshez admin szerepkörű fiók szükséges.
Szerver-infrastruktúra
Az alkalmazás egy RackHost.hu-n bérelt VPS szerveren fut Ubuntu 22.04 LTS operációs rendszeren. A szerveren fut a MySQL adatbázis, a WildFly alkalmazásszerver a backend WAR-fájlával, és a Cloudflare Tunnel daemon, amely az API biztonságos HTTPS-elérését biztosítja portnyitás nélkül.
A backend API az éles környezetben az alábbi alap URL-en érhető el:
https://api.carcomps.hu/vizsgaremek-1.0-SNAPSHOT/webresources/
Szerverhozzáférés
A szerver SSH-kapcsolaton keresztül érhető el. Biztonsági okokból a hozzáférési adatok (felhasználónév, jelszó, szerver IP-cím) nem kerülnek nyilvános dokumentációba. Az elérési adatokat a csapat tagjai külön, biztonságos csatornán tartják nyilván.
ssh root@[szerver-ip]

UNIT TESZTELÉS
Frontend Tesztelés futtatása
A unit tesztek Cypress keretrendszer segítségével futnak. A tesztek futtatásához navigáljon a frontend projekt könyvtárába, majd indítsa el a Cypress futtatókörnyezetet:
npx cypress open
A megjelenő felületen válassza az E2E Testing módot, majd válassza ki a futtatni kívánt tesztfájlt.
Alternatívan headless módban, CI-környezetben:
npx cypress run
Backend Tesztelés futtatása
A unit tesztek JUnit 5 keretrendszer segítségével futnak, Maven build rendszeren keresztül.
A tesztek futtatásához navigáljon a backend projekt könyvtárába, majd futtassa az alábbi parancsot:
mvn test
Ez automatikusan lefordítja a projektet és lefuttatja az összes tesztet a src/test/java könyvtárból.
Az eredmények a konzolon jelennek meg, részletes riport pedig a target/surefire-reports mappában érhető el.
Alternatívan, NetBeans IDE-ben jobb klikk a projekten, majd válassza a "Test" opciót.
a teszteredmények az IDE beépített tesztfuttatójában jelennek meg.
